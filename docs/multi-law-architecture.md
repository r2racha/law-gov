# โครงสร้างเว็บไซต์กฎหมายหลายฉบับ

## แนวทางที่เลือก

เว็บไซต์เดียวใช้ **กฎหมาย 1 ฉบับต่อ 1 ชุดข้อมูล** และมี `manifest` กลางสำหรับแสดงรายชื่อกฎหมายบนแท็บด้านบน ผู้เรียนเลือกแท็บเพื่อสลับเนื้อหา โดยคงรูปแบบหน้าบทเรียน รายมาตรา สรุป และข้อสอบแบบเดียวกับฉบับปัจจุบัน

```text
client/src/data/laws/
├── index.ts                 # manifest รายชื่อกฎหมายและตัวโหลดข้อมูล
├── administrative-procedure.ts
├── civil-service.ts
├── local-administration.ts
└── ...
```

แต่ละโมดูลส่งออกข้อมูลมาตรฐานเดียวกัน ได้แก่ รหัสกฎหมาย ชื่อเต็ม ชื่อย่อ สี/ภาพประกอบ บทสรุป รายมาตรา และข้อสอบ 20 ข้อ การแยกไฟล์ทำให้สามารถใช้ `import()` เพื่อโหลดเฉพาะกฎหมายที่ผู้เรียนเลือก ลดขนาด JavaScript แรกเริ่มและทำให้แท็บสลับฉบับได้โดยไม่ต้องมี server

## การนำทาง

แถบด้านบนควรประกอบด้วยปุ่ม “เลือกกฎหมาย” บนมือถือ และแท็บเลื่อนแนวนอนบนจอใหญ่ ตัวอย่าง URL คือ `/#/law/administrative-procedure` เพื่อให้แชร์ลิงก์ไปยังฉบับกฎหมายหรือหน้าที่ต้องการได้โดยตรง โดยไม่พึ่ง backend ของ GitHub Pages

เมื่อเปลี่ยนกฎหมาย เว็บไซต์จะรีเซ็ตสถานะค้นหา หมวดที่เลือก คำตอบข้อสอบ และตำแหน่งอ่าน จากนั้นโหลดข้อมูลของฉบับใหม่ นอกจากนี้ควรมีป้ายบอกสถานะ “กำลังอ่าน: …” เพื่อป้องกันผู้เรียนสับสนเมื่อแต่ละฉบับมีชื่อหมวดหรือเลขมาตราซ้ำกัน

## กรอบปริมาณที่แนะนำ

สำหรับกฎหมาย 10–15 ฉบับ ให้เก็บเฉพาะข้อมูลข้อความและภาพประกอบที่บีบอัดแล้วในเว็บไซต์ แต่ใช้ลิงก์ CDN สำหรับภาพ PNG ขนาดใหญ่ ไม่ควรฝังภาพเป็น base64 ใน JavaScript และควรแยกไฟล์ข้อมูล/ข้อสอบต่อฉบับ ขนาดเป้าหมายของข้อมูลข้อความต่อฉบับควรอยู่ราว 0.1–0.5 MB หลังบีบอัด ซึ่งทำให้ทั้งชุดยังอยู่ห่างจากขนาดเว็บไซต์ Pages 1 GB อย่างมาก

## ลำดับการเพิ่มกฎหมายใหม่

1. ตรวจสอบตัวบทฉบับที่มีผลใช้บังคับ แล้วสร้างไฟล์ข้อมูลตาม schema กลาง
2. เขียนคำอธิบายภาษาชาวบ้านและข้อสอบตามโครง 20 ข้อของเว็บไซต์
3. เพิ่มรายการเข้ากับ manifest และกำหนดสี/ภาพพี่ราชที่ใช้ชี้นำเนื้อหา
4. ทดสอบการเปลี่ยนแท็บ URL การค้นหา และแบบทดสอบของกฎหมายฉบับนั้น
5. build และเผยแพร่ผ่าน workflow เดิมของ GitHub Pages
